# 方块当前视觉测量接续修复

当前方块入口为 `scripts/run_physmani_cube.py`，选择本目录的 `native_worker.py`、`observer.py`、`tracker.py` 与 `producer.py`。任务预算仍为用户指定的 60 秒／1200 个原始 50 ms 物理步。

## 这次修改

原神经网络使用以公开目标球为中心的 64×64 局部裁剪。远离目标球的方块主要由原全图红色点云分支提供位置。失败复现中，方块仍可见，但转动后的点云不再符合旧分支的世界轴对齐几何假设，导致当前位置被拒绝。

新接续仅在原位置测量失败、最近 250 ms 内有真实目标观测时启用。它使用当前相机的红色深度分量拟合已知 50 mm 方块，内部允许转动；要求至少三个相机、三个表面、足够的对侧支持，并检查 95%／99% 表面误差不超过 3／5 mm。还保留原因果关联范围、桌面高度先验及远离目标球的限制。多解或缺少支持时仍返回不可用，不插值成观测。

原近场 NN 路线、权重与输入格式保留。新接续是**开发测量路线**，不继承旧 NN 的资格证书。内部拟合旋转用于定位，NN 仍收到原来的未观测单位旋转先验；没有宣称训练了完整姿态估计。模型接收的当前位置值可能改变，此变化已在每帧诊断和控制合同中披露。

不同测量分支的真实位置使用同一物理坐标／时间历史。切换分支不再自动清空 GRU 窗口；真实缺测仍会重启窗口，没有填造帧。

## 证据与边界

- 同一段记录的 100 帧：原测量可用 61 帧，新路线可用 100 帧。见 `current_frame_replay_v3/`。
- 严重丢测的高速开发样例 `2611113603` 修复后在 4.45 秒触发原生成功；原失败普通样例 `2611113700` 在 3.05 秒成功。
- 同组高速样例 `2611113602` 到 60 秒仍未成功，存在速度／位置联合跟踪及后续视觉不可用问题，不能宣称高速全部修好。
- 原成功的三个开发样例在新测量路线下仍全部成功。新固定四样例回归结果单独记录，不能与上述调试样例混为独立测试。

最终固定的新四例均按原生 `task.success()` 通过：

| 类型 | 成功数 | 原生成功时间 |
|---|---:|---|
| 高速 | 2/2 | 2.55、5.30 秒 |
| 普通速度 | 2/2 | 2.70、2.65 秒 |

这只是小规模、预先固定的新开发样例，不是总体成功率或正式 VAL／TEST。原六个开发样例的配对回归为高速 3/4、普通 2/2，合计 5/6；旧结果是 3/6。两轮最大预算分别为旧 16 秒和新 60 秒，不能称完全同预算比较，但新成功的五例均在原 8 秒内结束。

90 项测试通过。最终七例运行（原成功三例＋新固定四例）全部执行完毕、场景关闭、父进程实际 wait 返回 0、无未回收子进程、运行时来源未改变。详见 `selected_regression7_v1/actual_exit.json`。完整统计、未通过案例及停止／未运行实验分母见 `artifacts/framework/perception_repair_20261111_v1/report.json`。

以上产物位于 `artifacts/framework/perception_repair_20261111_v1/`。保存了原始 RGB-D、冻结 NN 的分割回放、点云拟合诊断、实际关节命令及 Native 成功记录。

主动控制与机械臂静止的同初态对照表明，静止时正常反弹，某些抓取轨迹接触后会出现方块转动及后续越界。原任务的边界逻辑依赖动态物体当前位置，可能与接触相互影响；这不是单凭日志就能归为渲染器故障的问题。本次没有修改原任务、场景、运动分布、抓持 API 或 `task.success()`。

## 未采用的控制实验

本目录 `coordinator_v2` 至 `v4`、相应 producer/worker 是保留的控制实验，**当前默认入口不使用**。恢复预抓取高度、同步后缓降、提高控制器规划速度等组合出现回归，因此没有将其作为有效修复交付。被终止的实验保留停止原因及未运行分母，不报告为完整成功率。

当前有效变更是上述感知接续与真实历史维护；执行控制仍使用此前的参数。成功仍只按原生任务结果，每个真实物理步检查，首次成功立即停止。没有使用 Native 目标位姿、速度真值或未来轨迹作为策略输入。
