# PhysMani 执行器与高速控制

当前入口仍为 `scripts/run_physmani_cube.py`，已接上 `our_mani/perception_repair_20261111_v1/native_worker.py` 的感知接续修复；执行控制沿用本目录既有版本。默认预算为用户指定的 **60 秒 / 1200 个原始 50 ms 物理步**。命令接口详见 `our_mani/execution_interface_20261111_v1/README.md`，本轮修改与验证边界见 `our_mani/perception_repair_20261111_v1/README.md`。

当前控制链使用位置伺服响应标定、远距离反馈跟踪、近距离四步公开预测 QP、关节限位刹车包络，以及原碰撞检查和后续刹车轨迹检查。额外响应误差余量属于优先尝试项；每次是否采用余量及回退结果均记录。碰撞检查仍是离散采样，不声明连续路径安全证明。

冻结候选 Transformer 和 GRU 的输入与权重保持原样。控制侧在已从相机观测到足够折返点时，使用因果反射残差修正；否则沿用 GRU。真实 `held` 只用于接触后的抬升／搬运，任务成功唯一依据仍是原生 `task.success()`，每个实际物理步采样并在第一次成功立即停止。没有读取原生方块位姿或未来轨迹控制机器人。

新增求解依赖为 `osqp==1.1.3`，本机项目环境和 Native 环境均已安装。见 `requirements-executor-20261111.txt`。

## 已验证的范围与限制

冻结的 16 秒六例开发回归见 `artifacts/framework/highspeed_control_20261111_v1/frozen_validation6_16s_v2/`：高速 2/4，普通 1/2。成功时间分别为高速 3.25、2.80 秒及普通 2.75 秒。另三个样例均到 16 秒仍未成功，存在公开视觉测量丢失及追踪问题。因此不能声称高速或普通任务已全面修好，延长预算也不能代替处理这些问题。

这六例都运行完成、原生场景关闭、父进程实际 wait 完成，没有遗留子进程，运行时来源未变化。60 秒通用后端计时检查与策略成功率单独记录；尚不把 16 秒结果当作 60 秒策略回归结果。

目录中的 `v1` 至 `v18`、早期线性／非线性 QP、间断观测恢复等均保留为开发与历史证据。当前入口选择感知修复包的明确版本，执行控制沿用 `v18` 的实现；未接管旧训练、旧模型或历史正式评估队列。
