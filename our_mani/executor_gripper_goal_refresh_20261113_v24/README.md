# 放杯夹爪事件期间的目标刷新回归

本版本只修复协议桥中的一个等待问题。旧实现已经接受同阶段的松手事件，
若调用者在手指实际张开之前暂时改回闭合，桥会等待原事件完成，并停止接收
该阶段的新位姿。若松手还在等待精确位置门限，这会让控制器追踪越来越旧的
目标，精确门限也无法满足。

现在保留已接受的开合事件，同时接受相同阶段的新位置、姿态、观测时间和
显式预测时长。跨阶段仍等待真实的夹爪完成确认。协议 envelope 仍是版本 2，
旧 8 维路由、物理开合、关节连续性、速度／加速度／jerk 限制均沿用原实现。

四个配对样例只更改此桥行为，沿用 v22 的 5 mm 释放位置门限、0.03 rad 姿态
门限、60 秒时限、TRAIN 专家目标和原生 Task.success。全部属于执行器诊断，
不是模型评估或正式 VAL／TEST；NN 和 optimizer 均不运行。
